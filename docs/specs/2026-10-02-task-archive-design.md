# Reversible Task Archive Design

Tasks keep their current status, description, priority, parent, identity, messages, images, and existing history when archived. Schema version 8 adds `tasks.archived INTEGER NOT NULL DEFAULT 0 CHECK(archived IN (0,1))`, replaces the ready-queue index with one restricted to unarchived new tasks, and rebuilds `events` so its action CHECK accepts `archive` and `unarchive`. Migration preserves task and event IDs, timestamps, and SQLite autoincrement sequences. Legacy rows become unarchived. Concurrent openers use the existing immediate migration transaction and version recheck.

`qqq archive ID` and `qqq unarchive ID` accept positive IDs or negative creation indexes. They return the task, update `archived` and `updated_at`, and append one event with the supplied session or `cli` as actor. Repeating an operation returns the same task without another event or timestamp change. `show`, `edit`, message, and image export by explicit ID remain available for archived tasks. JSON task values include boolean `archived`; human task summaries and `show` display `Archived: yes/no`.

Default `list`, `list --watch`, `tui`, continuous editor browsing, and claim/ready checks exclude archived tasks. `list --include-archived` and `tui --include-archived` reveal them. Human lists prefix archived descriptions with `[archived]`; JSON keeps the unmodified description. Existing `list -a` still controls completed-task display only. Completed-task limits count visible completed tasks, so hidden archived completions cannot consume the limit. An archived completed parent continues satisfying child readiness.

Archiving an in-progress task fails. Archiving an unfinished task (`new` or `error`) fails if it has any non-archived unfinished direct child. The same invariant rejects creation, reparenting, or unarchiving of an unfinished child under an archived unfinished parent. Checks and mutations share an immediate transaction, so concurrent claims and archive operations cannot race around the decision. Rejected operations leave task, events, and attachments unchanged. Completed children can remain visible under an archived unfinished parent because they need no future claim.

Tests cover v7 migration and concurrent opens, preservation of event history and image metadata, archive/unarchive idempotence, active-task rejection, nested dependencies, default and explicit CLI/TUI visibility, JSON and human output, completed-task limits, and distinct-session concurrent claims.
